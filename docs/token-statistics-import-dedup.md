# 会话导入后的 Token 重复统计修复

基于 `main` 的 `ad95beb`，分支 `codex/fix-import-token-double-count`。

## 问题与修复范围

导入会话会分配新 ID，跨账号复制也会生成消息文件副本。原统计按文件累加历史 usage，导致没有新模型请求也会增加输入、输出、缓存读写和调用次数。旧的逐文件日汇总缓存已丢失记录身份，不能在汇总后可靠去重。

修复仅改变 `scripts/token-stats.js` 的扫描、缓存和归属解析；`scripts/daemon.js` 的版本从 main 的 1.2.36 升到 1.2.37，并更新 build ID，使启动器能替换旧进程。没有修改会话文件、导入/复制流程、账户切换、积分账单接口或 UI。

## 统计规则

- 对解析后的完整 JSON 记录计算 SHA-256。副本中相同历史记录跨文件只统计一次，不仅按请求 ID 或 Token 数值去重，因此一个请求的不同记录、相同用量的不同调用仍分别计数。
- 相同记录在一个文件中出现多次时保留出现次数；其他文件的对应出现位置视为副本。这个规则针对当前导入/复制保留原消息内容的行为，不改变单文件内部的统计口径。
- 副本新增的消息单独计数。先跨文件去重，再应用账号、模型和日期筛选。
- 账号优先使用消息内明确的账号，其次使用原始 `sessionId` / `conversationId` 对应的账号。没有原始会话字段时保留文件归属回退；若同一记录的副本归属冲突，则只计入总量，不猜测归属。原始会话字段存在但该会话的归属已不可查时，也不把历史用量算到副本持有账号。
- 缓存版本升为 8，旧版本自动全量重建。按文件保存摘要和用量元数据，未变更文件不会因切换筛选条件而重新读取；账号归属使用最新映射，不固化在旧缓存中。缓存和 API 结果不包含消息正文或原始请求/消息 ID。
- 删除或更新副本后按现存文件重新合并；不保留已经没有任何文件承载的用量。没有时间戳的旧记录仍采用扫描时间回退，但重复导入优先保留较早的缓存观测日期。

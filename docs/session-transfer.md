# 会话大附件导入导出

会话导出曾在 `collectSessionArchiveFiles()` 和导入恢复处限制每个会话的附件总量为 256 MiB。旧链路同步读取所有附件并转为 Base64，再整体 JSON 序列化、gzip、加密以及前端文本下载，内存占用明显高于原文件大小。仅删除判断会暴露 V8 字符串长度和内存上限。

当前会话导出使用 `.wds` v4 流式归档，不设置附件单文件或总字节数上限。磁盘可用空间、文件系统和浏览器下载能力仍是实际约束；单次会话数 100、每会话文件数 20000 及元数据校验继续保留。

## 格式与传输

- 52 字节头：8 字节 `WDS4\r\n\x1a\n`、16 字节随机 salt、12 字节随机 IV、16 字节 GCM 标签。scrypt 派生 AES-256-GCM 密钥，头部前 36 字节作为 AAD。
- 加密内容是 gzip 流，内部用 4 字节大端长度加 JSON 元数据帧描述归档、会话和文件。文件帧后紧跟声明长度的原始字节，没有附件 Base64 或整体 JSON 字符串。单个元数据帧最多 1 MiB。
- `/api/sessions/export` 保持路径不变，返回二进制响应；先在私有临时目录完成加密再下载，避免将未完成归档当作成功。面板使用 Blob 下载。
- `/api/sessions/import` 的二进制请求先携带长度前缀 JSON（密码和可选目标账号），随后是原始归档。面板直接上传 File/Blob；密码不放进 URL 或日志。原有 API Token 和 Origin 校验不变。
- 导入先流式解密到私有临时压缩文件，完整验证 GCM 标签后再解压。解压附件写到内部生成的数字文件名；受管路径映射、重复路径及元数据校验通过后复制到新会话 ID，并写入数据库。外部 JSON 不能提供可信暂存文件路径。
- 失败时清理暂存目录；下载完成或中断后也清理导出目录。普通导入继续保留账号归属，指定目标账号时覆盖归属，不刷新或重启 WorkBuddy。
- 旧 v2/v3 `.json` 加密导出继续支持导入；旧格式仍走原来的内存解析路径。新 `.wds` 需要带本次修复的 WorkDaddy 才能导入。

## 验证

`test/session-transfer.test.js` 覆盖 257 MiB 单附件往返与 SHA-256 一致性、错误密码/篡改/截断、源文件大小变化、分段上传、空文件与多会话、路径穿越/重复/超大元数据拒绝，以及真实 HTTP 导出/导入路由和账号归属。

257 MiB 用例已在 `node --max-old-space-size=96` 下通过；这是 JavaScript 堆限制验证，不代表进程总内存只有 96 MiB。旧加密格式及历史 Token 去重回归测试仍通过。

本机 WorkBuddy 的 CDP 端口不可用，未验证实际客户端中的下载/文件选择交互；Windows 构建机不可连接，Windows 文件读写及安装包运行验证未执行。

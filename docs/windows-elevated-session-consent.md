# Windows 管理员会话兼容安装

## 原因与行为

旧版 Setup 的“继续管理员安装”只允许复制文件，并跳过进程清理和安装后启动；选择没有保存到启动器。内建 Administrator 或关闭 UAC 的桌面本身也可能是 elevated，快捷方式无法借用普通桌面令牌，最终仍以错误码 5 退出。

新版本仍优先使用普通权限。仅在原生 helper 确认以下条件后，安装器才展示“我已了解风险，继续安装”：当前进程和桌面均为 elevated、桌面 Explorer 路径正确、桌面属于当前用户，且桌面令牌为 TokenElevationTypeDefault（无关联的标准令牌）。手动提权的 Explorer 如果还有关联标准令牌，不适用此例外；检测失败也不适用。

风险说明明确告知：WorkDaddy、由它启动的 WorkBuddy，以及 WorkBuddy 中的命令、插件和自动操作将拥有更高权限，误操作可能影响系统文件和设置。窗口默认聚焦“取消安装”。

## 选择如何生效

- Setup 用自身实际权限运行只读检测 helper；用户明确点击继续后，才保存选择并进入精确进程清理、复制和安装后启动。
- 同意记录保存在各 profile 数据目录的 `windows-elevated-consent.json`，绑定版本化的同意格式、Windows 用户 SID、profile 和安装目录；不会放进发行包。
- 原生快捷方式和旧 `launcher.cmd` 入口共用原生 helper 验证。兼容模式下，旧脚本入口转入同一套原生启动流程。
- 每次 elevated 启动或生命周期操作重新检测桌面，确认记录仍适用。恢复普通权限桌面后，优先恢复普通权限启动。
- 静默安装只可沿用既有有效记录，不会显示或自动接受风险窗口。首次安装需要用户交互。
- 后台服务通过原生 helper 检测实际权限；不能再把 `WBSWITCH_NATIVE_LAUNCHER=1` 当成普通权限证明。
- 结束进程仍保留原有精确路径、PID、profile 和身份检查，并在实际终止句柄上核验用户、Windows 会话和提权状态一致；不请求 UAC、不按进程名批量结束，也不跨用户、会话或权限终止。

可关闭 WorkDaddy 后删除对应同意记录以撤销兼容模式；再次以管理员会话启动时需要重新安装并确认。普通 Windows 上手动“以管理员身份运行”安装器的原有提示仍保留，不会因此自动获得兼容模式许可。

## 验证边界

自动测试覆盖安装确认与各入口的连接、原生权限查询的有效/无效响应、daemon 权限与版本匹配，以及直接编译运行原生同意策略函数的持久化、损坏文件、不同用户、不同 profile、不同安装路径、桌面恢复普通权限等拒绝场景。便携策略测试仅替换 Windows 系统探测，不替换同意判定函数。

Windows/amd64 原生启动器可在 macOS 交叉编译。当前 Windows 测试主机连接超时，尚未完成 Inno Setup 编译、风险窗口视觉检查和真机安装/启动/升级；交叉编译及静态断言不能代替这些检查。

发布前应在隔离的 Windows 测试环境完成：

1. 普通 UAC 桌面：正常安装，以及手动提权启动后降回普通权限；不得出现管理员会话兼容提示。
2. 内建 Administrator/关闭 UAC 桌面：取消风险窗口后不启动；明确同意后安装、首次启动及再次双击均成功，后台实际报告 elevated。
3. 同一桌面分别安装 CN 和 AI：授权、数据、快捷方式、端口和进程清理各自独立，两客户端可同时运行。
4. 已同意的安装运行中升级、旧脚本入口启动、卸载；同时验证外来用户/会话/权限的进程不会被终止。
5. 无同意记录的静默安装必须停止；有匹配记录的静默更新可以继续。恢复普通桌面后旧记录不得让启动器保留 elevated。
6. 检查长风险说明在常用 DPI 下完整显示，取消默认聚焦，Esc 可以取消；确认后续真实快捷方式使用本次编译的原生 EXE。
